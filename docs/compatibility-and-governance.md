# 兼容性与记忆治理

## 当前定位

MemCube 提供的是记忆治理原则：来源、置信度、时效、冲突和可追溯升级。它不是对任何现有记忆插件的替代品，也不应与运行时记忆系统形成双写。

## 与现有记忆系统共存

| 现有能力 | MemCube 可以借鉴的部分 | 不应做的事 |
|---|---|---|
| 精确对话召回 | 根据来源回查原始证据 | 复制或替代召回索引 |
| 语义/场景记忆 | 区分事实、推断和过时状态 | 用 Markdown 正则覆盖结构化存储 |
| 自动记忆整理 | 记录升级理由与来源 | 再启动第二个整理器同时写入 |
| Skill 结晶 | 在证据充分时形成候选规则 | 根据一次聊天自动创建或安装 Skill |

## 单一写入源原则

一个运行时只应有一个长期记忆主写入源。额外工具默认只读，用于诊断、质量检查或迁移；任何写入必须走宿主已有的受控写入通道，并遵守其权限和用户确认要求。

## 推荐元数据

当宿主支持时，可将下列字段作为治理概念，而非强制 Markdown 格式：

- `confidence`：`verified` / `inferred` / `speculative`
- `source`：用户直接陈述、运行观察、推导或外部资料
- `status`：`active` / `outdated` / `archived`
- `updated_at`：最后核验时间
- `lineage`：能回查的原始来源或证据

## 工具边界

`memctl.py` 是轻量、只读的 Markdown 诊断脚本，适合演示简单的 `check`、`search`、`stats` 和 `evolve-dry-run`。它不应直接解析或改写复杂的插件管理区域，也不应在每个会话强制运行。

在真实生产记忆系统中，先用原生检索/写入接口；只有当原生能力不足时，才把 MemCube 的规则作为补充。
